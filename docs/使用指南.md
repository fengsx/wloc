# WLOC 使用指南（fengsx 个人部署）

适用设备：iPhone 13 mini，iOS 26.5。本文使用你自己的 [GitHub 仓库](https://github.com/fengsx/wloc) 和 [Cloudflare 选点服务](https://wloc.myfeng.workers.dev/)。

> WLOC 修改 Apple 的 Wi‑Fi／基站网络定位响应，不修改 GPS 硬件数据。iOS 26.5 的实际效果必须在你的手机上验证；即使网页显示保存成功，系统仍可能使用真实 GPS 或缓存位置。

## 1. 准备

1. 在 iPhone 上准备支持 **脚本、HTTP 响应改写、二进制响应体和 HTTPS 解密（MITM）** 的代理客户端。此仓库提供 Surge、Quantumult X、Loon、Stash、Shadowrocket 五种模块。选择你已经使用的客户端即可。
2. 确认代理客户端能正常连接，状态栏出现 VPN 标识。
3. 如果以前安装过任何 WLOC 模块，先在客户端中将旧模块停用，避免同一请求被多次改写。
4. 用 Safari 打开 [选点服务](https://wloc.myfeng.workers.dev/)，确认首页能显示地图和“模块订阅地址”。若地图空白，先检查手机是否能连接地图图层与 `unpkg.com`。

## 2. 安装你的模块

只复制与你的客户端对应的一条 URL，在客户端的“模块／插件／重写／覆写”页面以 URL 订阅并启用。不要直接使用已失效的 `Yu9191/wloc` 地址。

| 客户端 | 订阅 URL |
| --- | --- |
| Surge（Egern 可尝试此格式） | https://raw.githubusercontent.com/fengsx/wloc/refs/heads/main/modules/wloc.sgmodule |
| Quantumult X | https://raw.githubusercontent.com/fengsx/wloc/refs/heads/main/modules/wloc.conf |
| Loon | https://raw.githubusercontent.com/fengsx/wloc/refs/heads/main/modules/wloc.lpx |
| Stash | https://raw.githubusercontent.com/fengsx/wloc/refs/heads/main/modules/wloc.stoverride |
| Shadowrocket | https://raw.githubusercontent.com/fengsx/wloc/refs/heads/main/modules/wloc.module |

常见入口：Surge 的“模块 → 安装新模块 → 从 URL 安装”；Loon 的“配置 → 插件 → 添加 URL”；Shadowrocket 的“配置／模块 → 添加 URL”。菜单名称会随客户端版本变化。Stash 使用 `.stoverride` 原生覆写文件。

导入后确认模块处于启用状态。模块脚本应从 `raw.githubusercontent.com/fengsx/wloc` 下载；如果仍显示 `Yu9191` 或 `xepes0`，说明导入的是旧地址。

## 3. 配置 HTTPS 解密和证书

WLOC 模块需要拦截 Apple 网络定位请求。仅订阅模块并不足以生效。

1. 在代理客户端中开启 **MITM／HTTPS 解密**。模块声明的域名包括 `gs-loc.apple.com`、`gs-loc-cn.apple.com`、`gsp-ssl.ls.apple.com` 及高德相关定位域名；确认客户端实际启用了对应主机名。
2. 使用**你自己的代理客户端**生成并安装 CA 证书描述文件。iPhone 路径通常是“设置 → 通用 → VPN 与设备管理”。
3. 再到“设置 → 通用 → 关于本机 → 证书信任设置”，对该客户端生成的根证书打开“完全信任”。安装描述文件和完全信任是两步。
4. 回到代理客户端，确认 VPN、WLOC 模块、MITM 都仍然开启。证书只应来自你信任的客户端；不要安装陌生人提供的 CA 私钥或描述文件。

## 4. 设置虚拟位置

1. 保持代理客户端连接，让 **Safari 流量经过它**，打开 [https://wloc.myfeng.workers.dev/](https://wloc.myfeng.workers.dev/)。
2. 在地图上选点、搜索地点或粘贴地图分享链接。页面内显示的经纬度是准备写入设备的目标值。
3. 点击“**储存到设备**”。页面会请求 `https://gs-loc.apple.com/wloc-settings/save?...`，手机本地的 WLOC 模块负责拦截并保存坐标。Cloudflare Worker 只提供网页和地图链接解析，不保存手机端的生效坐标。
4. 点击当前坐标区域的“刷新”，核对回读的经纬度。网页显示“已储存”只证明设置脚本返回成功，**不能证明 iOS 已采用该位置**。

首次测试建议选择一个和真实位置明显不同、但便于核对的地点。不要在经度或纬度恰好为 `0` 的位置测试：当前脚本对零度坐标有已确认的读写问题。

## 5. 在 iOS 26.5 上刷新定位并验证

先完成上一步的保存，再按以下顺序处理缓存：

1. 在“设置 → 隐私与安全性 → 定位服务”关闭总开关。
2. 开启飞行模式，并确认 Wi‑Fi、蓝牙也已关闭。
3. 重启 iPhone。iOS 26 系列可能长时间复用 `locationd` 缓存，重启通常比反复切换飞行模式更可靠。
4. 开机后关闭飞行模式，等待网络恢复；重新连接代理客户端，确认 VPN、模块和 MITM 均已生效。
5. **最后**重新打开定位服务。
6. 完全退出并重新打开 Apple 地图，在室内或 GPS 信号较弱的环境查看蓝点。若客户端有脚本日志，检查 Apple `/clls/wloc` 响应是否被脚本命中与改写。

若蓝点短暂跳到目标点又回到真实位置，通常是 GPS 覆盖了网络定位。WLOC 对每个 App 的效果不能保证一致。

## 6. 恢复真实位置

1. 在选点网页的当前坐标区域点击“清除数据”。
2. **关闭 WLOC 模块**。这样即使模块参数中曾写入固定坐标，也不会继续改写定位响应。
3. 重启 iPhone，确认网络和定位服务恢复，再打开 Apple 地图核对真实位置。

如果仍显示旧位置，检查是否有第二份旧 WLOC 模块仍在运行，并等待系统重新获取定位。确认不再需要 HTTPS 解密后，可在代理客户端内关闭相应 MITM 规则。

## 7. 故障排查

| 现象 | 优先检查 |
| --- | --- |
| 模块下载失败 | 手机能否打开上述 `raw.githubusercontent.com/fengsx/wloc` URL；是否仍引用已删除的原仓库。 |
| 地图网页打不开 | 代理连接、Cloudflare 地址、网络。 |
| 地图空白 | `unpkg.com` 的 Leaflet 资源或地图瓦片是否被阻断。 |
| “储存到设备”失败 | Safari 是否经过当前代理；MITM 是否开启；CA 是否“完全信任”；设置脚本是否命中。 |
| 保存成功但地图位置不变 | 重启清除缓存；等待 VPN 先恢复再开启定位；检查 `/clls/wloc` 日志；换到室内验证 GPS 覆盖。 |
| 当前坐标显示“无已保存的坐标” | 先检查保存请求是否命中；经纬度为 `0` 时当前版本也会错误地显示此信息。 |
| 恢复真实位置失败 | 关闭 WLOC 模块、排查重复模块和固定参数，然后重启。 |

## 8. 当前代码的注意点

- 手机端 `wloc-settings/save` 是由代理模块拦截的 GET/CORS 接口，没有身份验证。启用 MITM 时，不要在不可信网页中打开来自他人的“设置位置”链接；确认模块只从你的仓库订阅。
- 当前版本对缺失经纬度会错误写入 `0,0`，对真正的零度坐标又会错误判断为未保存。手动调用设置 URL 时务必提供合法的非零经纬度，日常请使用上面的选点网页。
- 公开的 `/api/parse` 会访问用户给出的地图链接。不要把带私人标记或敏感参数的分享链接发给不信任的人；第三方地图服务和托管平台仍可能处理相应网络请求。
- 仓库 README 中的 iCloud 快捷指令仍指向社区维护者的解析服务。要全程使用你自己的部署，优先采用本指南的网页选点方式；自行修改快捷指令时只将 `/api/parse` 的主机改成 `wloc.myfeng.workers.dev`，不要把 `gs-loc.apple.com/wloc-settings/save` 改成 Worker 地址。

## 9. 自己维护服务

GitHub 仓库 `fengsx/wloc` 的 `main` 分支已连接 Cloudflare Worker `wloc`。正常情况下，新提交会触发自动构建部署。项目配置在 `project.config.json`，Worker 名称在 `worker/wrangler.jsonc`；模块订阅文件由 `npm run configure` 生成。修改配置后运行 `npm run check:release`、`npm test` 和 `npm run build:check`，再提交推送。
